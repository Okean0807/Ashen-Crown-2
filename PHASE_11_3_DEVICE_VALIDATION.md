## 4. Временная диагностическая панель (Diagnostic Mode)

- **В обычном режиме (`/`):** полностью отключена и не рендерится (`diagVisibleNormal = false`), не влияет на игровые механики и цикл симуляции.
- **Способы включения/выключения:**
  1. Открыть URL с параметром **`?diag=1`** (или `?diagnostics=1`).
  2. Во время игры нажать **`Меню`** -> **`Диагностика: Выкл / Вкл`** -> **`Продолжить`**.
  3. На десктопе — клавиша **`F9`**.
  4. Нажать кнопку **`Скрыть`** прямо в заголовке диагностической панели.
- **Отображаемые показатели:**
  - `Renderer`: `WebGL (Three.js)` или `2D (Canvas fallback)`;
  - `FPS` и среднее время кадра (`ms`);
  - `Экран` (`CSS width×height`) и `Буфер` (физический размер канваса);
  - `DPR` (`window.devicePixelRatio` и фактический DPR рендерера с учётом мобильного лимита `<= 1.5`);
  - `WebGL`: `OK (WebGL2)` / `OK (WebGL1)` / `CONTEXT LOST` / `UNAVAILABLE` (+ флаг `SW` для программного WebGL и строка `GPU`);
  - `Объекты`: всего, `Юн` (живые юниты), `Зд` (здания), `Сн` (снаряды), `Чст` (частицы), а в 3D также `DC` (draw calls) и `Tri` (треугольники);
  - `Ошибки рендерера`: количество и список последних ошибок инициализации / `webglcontextlost` / `render()`.

## 5. Известные ограничения

1. **Аппаратная производительность 3D WebGL ещё не замерена на реальном GPU:** цифры `0–1 FPS` выше получены на CPU-эмуляторе SwiftShader и не отражают скорость на мобильных GPU (Adreno / Mali / Apple GPU). Требуется реальный замер на смартфоне.
2. **Количество draw calls в 3D (`265` на мобильном, `459` на десктопе):** на слабых/средних смартфонах при больших сражениях может потребоваться батчинг/инстансинг пропов и юнитов — решение будет принято по фактическому FPS с физического устройства.
3. **Размер production JS-бандла (`3.0 MB` / `631 KB gzip`):** первичная загрузка по мобильному интернету займёт 1–3 секунды (основную долю занимает `three`).
4. **Непроверенные особенности реальных мобильных браузеров (`PENDING_DEVICE_TEST`):** жесты края экрана iOS Safari (системный «Назад»), поведение адресной строки при изменении `100dvh`, нагрев устройства, стабильность WebGL-контекста при сворачивании/разворачивании браузера.
5. **Открытые дизайн-вопросы (`OPEN_ISSUES.md`):** `OD-001..020`, `AC-OWNER-001..006` и `OD-RUNTIME-001` (открытие сундука в реальном времени без автопаузы боя) остаются открытыми на решение владельца.
